# Web表示の観察

## 証拠として残す情報

ページごとにsource IDを付け、次を記録する。

- 入力URLと表示後のURL。共有する記録から認証用token等を除く。
- 取得日時（タイムゾーン付き）、ページ名、言語、テーマ、ログイン有無。
- viewportの幅・高さ（CSS px）、device pixel ratio、スクロール位置。
- 状態名とそこに至る操作。例：mobile/menu-open、desktop/default。
- ページ全体または区間ごとの画像。固定ヘッダー等が重複する場合は区間で比較する。
- 取得方法：rendered DOM、computed style、capture、user screenshot等。
- 未読込画像、未取得領域、再現できなかった状態、フォント読込状況。

私的な管理画面では値そのものが必要か判断する。パスワード、Cookie、認証情報、隠れた入力値を収集しない。見本値に置き換えた場合は記録する。

## 実際の表示を読む

1. ブラウザで対象URLを開き、フォント・画像と表示が落ち着いたことを確認する。通信が続くサイトでnetwork idleだけを永久に待たない。
2. 指定幅でページ全体をスクロールし、遅延読込を発生させる。先頭に戻して比較用の画像を得る。動画は比較する静止時点を記録する。
3. consent、広告、地域、ログイン、A/Bテストで表示が違う場合は条件を残す。避けるために同意設定やアカウント設定を勝手に変更しない。
4. 繰り返す見た目・構造を調べる。ボタン、リンク、見出し、入力、カード、ナビゲーション、メニュー等を対象ページから抽出する。
5. mobileも実際に表示して、順番、折返し、非表示、メニュー切替を確認する。desktopを縮小しただけでmobile扱いしない。

## DOM/CSSを読める場合

許可されたブラウザ機能の範囲で代表要素のcomputed styleと寸法を読む。全DOMを無制限に出力する必要はない。

| 対象 | 観測する値 |
|---|---|
| 文字 | family、実際の使用フォントが分かればその情報、weight、size、line-height、letter-spacing、色、装飾、改行 |
| 構造 | display、flex/grid、方向、gap、alignment、padding、margin、min/max幅、bounding box |
| 表面 | 背景・透明度、枠線、角丸、影、gradient |
| 画像 | currentSrc、表示寸法、object-fit、object-position、alt、取得可否 |
| アイコン | SVG/vectorか、画像か、icon fontか。元assetまたは実際の形状 |
| token候補 | 観察要素が使うCSS custom propertiesと解決値。元の名前も残す |

font-family宣言だけでは実際のフォント使用を保証しない。フォント未読込やfallbackをチェックする。computed styleの値だけでは設計意図や正式なtoken名は分からない。

閉じたShadow DOM、cross-origin iframe、Canvas、WebGL、アクセス制限内のCSSは取得できないことがある。視覚的な観察で補い、取得できない内部構造は未知として記録する。

## 実測・推定・整理を区別する

- `observed`：DOM/CSS、取得した素材、実画面で確認した情報。数値の出典も付ける。
- `estimated`：画像から推定したフォントや寸法。理由と、検証できる条件を添える。
- `derived`：今回のmasterのために付けた意味名や再利用単位。値自体が実測なら、その実測への参照を付ける。
- `unknown`：未観察・取得できない情報。仮の状態を作って埋めない。

例えば「primaryという名前」はderived、「背景色#123456」はcomputed styleがあればobserved。画像だけから読んだ色は、画像圧縮や合成の影響を受ける推定値として扱う。

## 状態とページ範囲

hover、focus、開閉は安全に観察できる範囲で確認する。フォーム送信によるエラー、決済、外部連携の完了状態は、既存画面・提供された資料・明示されたテスト環境を使う。検証のためだけに実データを書き換えない。

ページ一覧に「予定／観察済み／作成済み／検証済み／取得不可」を記録する。同一テンプレートの別記事を省略したなら、その事実を範囲として示す。「任意のWebサイトに対応」は入力を特定サービスに限定しない意味であり、アクセス制限の突破や未公開状態の再現を意味しない。
