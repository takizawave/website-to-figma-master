# Website → Figma Master

**WebサイトのURLを渡して、Figmaで使い回せるデザインの土台を作る。**

ChatGPT / Claude向けのスキルです。「スキル」は、AIに毎回同じ手順で作業してもらうための説明書。コードを書く必要はありません。

画面を再現するだけでなく、ボタンやカードを部品にし、色・文字・余白も整理します。さらに、**毎月の画面をsnapshotとして残す**手順が入っています。

## まずはこれだけ

| 使うもの | ダウンロード | 次にやること |
|---|---|---|
| **ChatGPT** | [添付用ファイルをダウンロード](https://github.com/takizawave/website-to-figma-master/raw/refs/heads/main/downloads/website-to-figma-master-chat.md) | 新しいチャットに添付して、下の依頼文を送る |
| **Claude：まず試す** | [同じ添付用ファイルをダウンロード](https://github.com/takizawave/website-to-figma-master/raw/refs/heads/main/downloads/website-to-figma-master-chat.md) | 新しいチャットに添付して、下の依頼文を送る |
| **Claude：繰り返し使う** | [登録用ZIPをダウンロード](https://github.com/takizawave/website-to-figma-master/raw/refs/heads/main/downloads/website-to-figma-master.zip) | 下の「Claudeに登録する」へ進む |

ファイルがブラウザに表示された場合は、そのファイルを保存してください。GitHub上部の **Code → Download ZIPは、Claudeへの登録用ではありません。** 表の「登録用ZIP」を使ってください。

### 1. 用意する

- 再現したいWebページのURL。
- ChatGPTまたはClaude。
- Figmaアカウント。既存ファイルに追加したい場合は、その編集可能なファイルのリンク。

AIがFigmaへ直接作成するには、**Figmaを編集できる接続**が必要です。接続の名前や設定は使う環境によって異なるため、次の依頼文には機能確認も含めています。まだ接続していなくても、まず依頼して構いません。

### 2. 添付して、この文章を送る

**「ここにURLを貼る」だけ置き換えてください。** 保存先を指定したい場合は「新しく作ってください」をFigmaのリンクに置き換えます。

```text
添付したwebsite-to-figma-masterの手順を使って、
次のWebサイトからFigmaのmaster designを作ってください。

対象URL：ここにURLを貼る
対象範囲：このページ
Figma保存先：新しく作ってください
画面サイズ：PCとスマートフォン

文字や配置を編集できる画面にしてください。
ボタンやカードは再利用できる部品にして、色・文字・余白も整理してください。
実際に確認した情報と、画像から推定した情報は区別してください。

毎月1回、Figmaにある画面をsnapshotとして保存してください。
後から部品や色を変えても、過去の見た目が変わらないようにしてください。
過去分は消さないでください。

最初に、Web画面の確認・Figmaへの書き込み・定期実行が使えるか調べてください。
足りない機能があれば、私が次に何をすればよいか、画面上の操作で説明してください。
```

### 3. 結果を確認する

Figmaのリンクが返ってきたら、次の3つを見てください。

- **文字をクリックして編集できる？** 画面全体が1枚の画像になっていないか確認します。
- **ボタンやカードを部品として使える？** `02 Components`を開きます。
- **PCとスマートフォンの両方がある？** `03 Screens`を開き、元ページと見比べます。

依頼した範囲に作れない部分があれば、AIが理由を残します。「取込待ち」「視覚検証待ち」は作業途中です。

## 何ができるの？

このスキルでいう **master design** は、今後のデザイン作業で使い回せる「画面・部品・スタイルのセット」です。

| Figmaのページ | 入っているもの | 使う場面 |
|---|---|---|
| `00 Source` | 元サイトのURL、取得日時、画面サイズ | 何を元に作ったか調べる |
| `01 Foundations` | 色、文字、余白、角丸、影 | 見た目のルールを確認する |
| `02 Components` | ボタン、入力欄、カードなどの部品 | 新しい画面で使い回す |
| `03 Screens` | PC・スマートフォンの画面 | 画面を編集する、構成を確認する |
| `04 更新履歴` | 更新する前と後の比較 | 何を変えたか確認する |
| `05 Snapshots` | 月ごとの固定記録 | 以前の画面を振り返る |
| `99 Notes` | 推定した値や再現できなかった部分 | 元サイトとの違いを確認する |

既存のFigmaファイルを使う場合は、その整理方法を尊重します。必ずこのページ名に変更するわけではありません。

## Claudeに登録する

毎回ファイルを添付したくない場合に使います。

1. 上の表から**登録用ZIP**をダウンロードする。解凍は不要です。
2. Claudeの **Customize → Skills** を開く。
3. **＋ → Create skill → Upload a skill** を選ぶ。
4. ZIPをアップロードし、スキルを有効にする。
5. 新しいチャットで、上の依頼文の最初を「website-to-figma-masterを使って」に変えて送る。

項目名や利用可否はアカウントによって異なります。Skillsとコード実行が有効である必要があります。[Claude公式の案内](https://support.claude.com/en/articles/12512180-use-skills-in-claude)

ChatGPTでもスキル対応環境に登録して使えますが、初めて使う方は上の添付方式で始めてください。添付しただけでは、別のチャットにも自動で引き継がれるわけではありません。[ChatGPT公式の案内](https://learn.chatgpt.com/docs/build-skills)

## 月1回のsnapshotはどう残る？

**その時点のFigmaの画面を、月ごとに固定保存します。**

初回は完成した画面を保存。その後は毎月1日09:00を初期設定として、ユーザーのタイムゾーンで保存します。日付・時刻は変更できます。

```text
05 Snapshots
├─ 2026-11 … 11月に保存した画面・部品・スタイル
├─ 2026-12 … 12月に保存した画面・部品・スタイル
└─ 2027-01 … 1月に保存した画面・部品・スタイル
```

これは保存構成の例です。このリポジトリに実際の画面が入っているわけではありません。

- 元の部品を変更しても、過去の画面が変わらないように固定します。
- 画面画像と、色・文字等の値も残します。
- 変更が無い月も保存します。過去分は自動で削除しません。
- 保存が遅れた場合は実際の取得日時を記録します。撮っていない過去の画面は作りません。

### 自動保存を始めるには

**ダウンロードやスキル登録だけでは、毎月の自動保存は始まりません。**

最初のmaster designができた後、AIが使える定期実行機能を確認し、対象のFigma・保存先・時刻を指定して設定します。設定できたら、タスクの登録結果と実行予定が返ってきます。通知するだけのリマインダーと、自動で保存するタスクは区別します。

定期実行が使えない場合は、月1回、この依頼文を送ってください。

```text
website-to-figma-masterの手順で、次のFigmaの当月snapshotを保存してください。
Figma：ここにファイルのリンクを貼る

前回の設定と記録を使ってください。今月分があれば重複して作らないでください。
Webサイトの再取得や現行画面の更新はせず、今ある画面・部品・スタイルを固定保存してください。
```

添付方式で新しいチャットから実行する場合は、スキルと、前回AIが返した設定・作業記録も添付してください。

**snapshotは「Figmaにある姿の保存」です。** Webサイトの変更を毎月取り込む自動更新は含みません。サイトを更新したときは、次の依頼を使います。

## サイトを更新した後の依頼

```text
website-to-figma-masterを使って、このWebページの変更をFigmaに反映してください。

Web：https://example.com/
Figma：ここにファイルのリンクを貼る

変更前の姿を先に残し、変更前と変更後を「更新履歴」で比較できるようにしてください。
当月snapshotが未保存なら、更新前に保存してください。過去のsnapshotは変更しないでください。
```

`https://example.com/`は説明用です。実際の対象URLに置き換えてください。

## うまくいかないとき

| 困ったこと | 次にやること |
|---|---|
| Figmaに作成されない | 「この接続でFigmaへの書き込みができますか？」と聞く。読取り専用の接続では作成できません |
| 「取込待ち」と言われた | AIが用意した取り込み手順を確認する。開発用プラグインが必要な環境では、Figma desktopでの操作が必要です |
| サイトがログイン画面になる | ログイン後の画面画像などを、利用が許可された方法で提供する。パスワードはチャットに貼らない |
| スマートフォン画面が無い | 実際にその幅で表示できたか確認する。見られない場合はスマートフォンの画面画像を提供する |
| フォントや画像が違う | `99 Notes`の代替・取得不可の記録を確認し、使える元素材を提供する |
| 毎月保存されない | 定期タスクが登録済みか、そのタスクがFigmaを編集・保存できるかを確認する |
| ClaudeがZIPを受け付けない | 上の「登録用ZIP」を使ったか確認する。リポジトリ全体のZIPや`.skill`ではなく`.zip`を選ぶ |

画像しかない場合、文字や配置は再構成できますが、フォントや寸法に推定が含まれます。ログイン制限、複雑なアニメーション、Canvas等があるサイトでは、全ての状態を忠実に再現できるとは限りません。

## 顧客情報について

**このリポジトリには、汎用の手順と空の設定例だけを収録しています。** 顧客名、実案件のURL、画面画像、認証情報は含めていません。

実案件で使った後に作られる設定、作業記録、画面画像、snapshotには顧客情報が含まれることがあります。それらは顧客・社内で許可されたFigmaや保存先に保管し、この公開リポジトリやIssueには貼らないでください。AIやFigmaへの入力は、所属組織と顧客の利用ルールに従ってください。

`.gitignore`には実案件の設定・取得画像・snapshot等を除外するための項目も入れています。ただし、名前が違うファイルまで自動的に安全にする仕組みではありません。
